# ESP32 积木与硬件控制网关项目开发计划书 (终版)

## 一、 项目概述

本项目旨在利用**现有的绝对最小化硬件配置**（ESP32板子、2个SG90舵机、杜邦线、手机/电脑/iPad、乐高 HUB、宇星模王 4.0 电池盒），在不增加任何额外预算、不剪线、不购买电机驱动板的前提下，闭环打造一个智能局域网（LAN）无线控制网关。

网关采用“**物理引脚直连控制现存舵机** + **软件模拟/蓝牙透传移动积木**”的并行流控策略。固定不动的 ESP32 扮演“Wi-Fi 转蓝牙”的边缘中继网关：左手通过 Wi-Fi（WebSocket）与局域网内多端网页维持全双工长连接，右手通过物理引脚控制 2 个本地舵机（模拟灯光与马达），同时利用 BLE 蓝牙协议在空气中锁定制动在轨道火车上的乐高 HUB 和宇星电池盒。

最终实现：**免 App 依赖、Wi-Fi 动态配网、多端网页状态毫秒级无缝同步、移动节点断线自动重连与防失控安全刹车。**

## 🛠️ 第一阶段：开发环境搭建与物理硬件通路验证

### 任务 1.1：Arduino IDE 开发环境搭建与库配置

- **需求描述：** 配置好能够编译并烧录 ESP32 的轻量级开发环境，并引入项目所需的全部第三方核心依赖库。

- **输入：** 电脑、ESP32 开发板、USB 数据传输线（拒绝纯充电线）。

- **输出：** 完成环境配置，成功编译并有线烧录基础 Blink 程序，串口能够正常通信。

- **具体执行步骤：**
  
  1. 下载并安装最新版 Arduino IDE。
  
  2. 在“首选项”中添加 ESP32 官方开发板管理器地址，并在“开发板管理器”中下载并安装 `esp32` 核心硬件支持包。
  
  3. 打开“库管理器”，搜索并依次下载安装以下四个核心库：
     
     - `ESPAsyncWebServer`：基于事件驱动的异步 Web 服务器，用于多端并发访问时不阻塞系统。
     
     - `AsyncTCP`：异步网络底层支撑库。
     
     - `ESP32Servo`：利用 ESP32 内部 LEDC（PWM 定时器）硬件外设封装的舵机驱动库。
     
     - `ArduinoJson`：用于前后端高频数据交互的轻量级 JSON 解析库。
     
     - `WiFiManager`：用于实现 Wi-Fi 动态配网的专属依赖库。

### 任务 1.2：现有物理舵机安全连线与驱动测试

- **需求描述：** 利用现有的杜邦线，将 2 个 SG90 舵机安全连接至 ESP32，验证引脚时序信号输出正常。

- **安全限制：** 鉴于调试期完全依赖电脑 USB 供电（5V, 约 500mA），2 个舵机仅做角度摆动逻辑实验，禁止加装任何重型积木负载，防止整板因堵转电流过载触发芯片欠压保护重启（Brownout Reset）。

- **输入：** ESP32 开发板、SG90 舵机 $\times 2$、杜邦线。

- **输出：** 编写测试代码，使 2 个舵机在 0° 至 180° 之间自动往复匀速摆动。

- **具体执行步骤：**
  
  1. **硬件连线（严格对照引脚）：**
     
     - 舵机 1（模拟灯光）：棕色线（GND） $\rightarrow$ ESP32 GND；红色线（VCC） $\rightarrow$ ESP32 VIN (5V)；橙色线（PWM信号） $\rightarrow$ GPIO 13。
     
     - 舵机 2（模拟马达）：棕色线（GND） $\rightarrow$ ESP32 另一个 GND；红色线（VCC） $\rightarrow$ 强行挤入同一个 VIN/5V 插孔（或利用导线拧紧）；橙色线（PWM信号） $\rightarrow$ GPIO 12。
  
  2. **代码逻辑编写：** 引入 `ESP32Servo.h`，在 `setup()` 中初始化并在 `loop()` 中通过 `write(angle)` 轮询写入角度（0.5ms - 2.5ms 脉宽），确保两个舵机运转平滑。

## 🌐 第二阶段：网络全双工通信与多端同步闭环

### 任务 2.1：动态 Wi-Fi 配网与 Web 服务器托管

- **需求描述：** ESP32 采用非硬编码联网方式。当环境 Wi-Fi 变更时能自动切换为 AP 热点模式供手机重新配网。联网成功后激活异步服务器，向访问其 IP 的设备返回全功能控制网页。

- **输入：** 连线完成的 ESP32、有线连接的电脑。

- **输出：** 手机访问 ESP32 IP 能够成功渲染出包含 4 个控制滑块（物理舵机 $\times 2$、乐高马达 $\times 1$、宇星马达 $\times 1$）与 3 个连接状态指示灯的静态网页。

- **具体执行步骤：**
  
  1. **集成 WiFiManager：** 代码中剔除 `WiFi.begin("SSID", "PWD")`，改用 `wm.autoConnect("QinBoss-Gateway")`。若 30 秒内连不上历史 Wi-Fi，板子自动广播名为 `QinBoss-Gateway` 的无密热点，用户用手机连入该热点即可在弹出的 Portal 网页中动态配置新 Wi-Fi。
  
  2. **Flash 内存优化：** 使用 `const char index_html[] PROGMEM = R"rawliteral(...)"rawliteral";` 语法，将包含 HTML/CSS/JavaScript 的网页源码死死刻在 Flash（闪存）中，绝不占用宝贵的 SRAM（运行内存）。
  
  3. **UI 部署：** 前端页面部署 4 个 `<input type="range">` 滑块及 3 个 `<span>` 状态指示灯标签。

### 任务 2.2：WebSocket 双向控制与多浏览器状态毫秒级同步

- **需求描述：** 放弃高开销的 HTTP 轮询，建立基于 WebSocket 协议的持久裸 TCP 双向“数据吸管”。实现实时控制与多端无刷新数据绝对同步。

- **输出指标：** 状态同步延迟小于 100ms，网页高频拖动不卡顿。

- **具体执行步骤：**
  
  1. **前端（JS）高频节流：** 初始化 `new WebSocket()` 连接。在滑块的 `oninput` 事件中加入 `setTimeout` 节流阀：**限制每 60ms-80ms 最多发送一次数据**，从源头上切断拖动产生的网络风暴，捍卫 ESP32 单天线的稳定性。
  
  2. **后端（ESP32）异步接收：** 注册 `AsyncWebSocket ws("/ws")` 通道。在消息接收回调（`WS_EVT_DATA`）中利用 `ArduinoJson` 解析来自前端的文本（形如 `{"device":"servo1","value":90}`），并立即驱动硬件。
  
  3. **全网状态广播：** ESP32 收到任意一端的数据更新后，立即调用 `ws.textAll(json)` 将最新状态主动推送到所有当前在线的客户端，前端 JS 接收后动态强行修改滑块的 `value` 属性，实现多端同步。

## 📡 第三阶段：开源 VB 协议提取与蓝牙（BLE）状态机开发

### 任务 3.1：BrickController 开源 VB 源码协议特征码提取

- **需求描述：** 深入剖析现有的 BrickController 开源 VB.NET 源码，将其中关于乐高 Powered Up HUB 和宇星模王 4.0 电池盒的蓝牙通信底层指令完全剥离。

- **核心输出：** 整理出一份十六进制硬核参数清单，包含：
  
  - **乐高官方 HUB 规范：** 服务 UUID (`00001623-1212-efde-1623-785feabcd123`)、控制特征 UUID (`00001624-1212-efde-1623-785feabcd123`)。调速输出采用 8 字节固定数组（例如 A 口转动：`0x08, 0x00, 0x81, 0x00, 0x11, 0x51, 0x00, 速度值`）。
  
  - **宇星模王 4.0 规范：** 提取直接写入特定特征值的 4-5 字节固定控制流（例如：`0x55, 通道号, 方向, 速度值`）。

### 任务 3.2：高级蓝牙主机（BLE Central）非阻塞状态机编写

- **需求描述：** 激活 ESP32 的蓝牙 BLE 模块扮演“主机（Central）”角色，编写异步扫描与连接逻辑，自动捕获并连接空气中的乐高 HUB 和宇星电池盒（从机/Peripheral）。

- **具体执行步骤：**
  
  1. 引入 `BLEDevice.h`，在 `setup()` 中初始化 BLE 并在后台开启异步扫描。
  
  2. 编写自定义扫描回调类，当扫描到的设备名或服务 UUID 与任务 3.1 提炼的特征匹配时，判定为目标火车，立即调用 `pClient->connect()` 建立一对一无线链路。
  
  3. 成功连接后获取对应的远程写特征（Remote Characteristic），封装标准的非阻塞字节流发送函数 `sendBleBytes()`。

## 🎛️ 第四阶段：全功能网关总组装与并发联调

### 任务 4.1：Wi-Fi 与蓝牙双模业务逻辑分流总组装

- **需求描述：** 将第三阶段的蓝牙控制函数嵌入到第二阶段的 WebSocket 接收逻辑中，正式打通“手机网页 $\rightarrow$ Wi-Fi $\rightarrow$ ESP32 网关 $\rightarrow$ 蓝牙 BLE $\rightarrow$ 火车积木马达”的全链路。

- **具体执行步骤：**
  
  1. **定义统一的通信数据报文：**
     
     JSON
     
     ```
     {
      "device": "servo1 | servo2 | lego | mouldking",
      "value": 0
     }
     ```
  
  2. **重构后端解耦分流器：** 在 WebSocket 的数据处理分支（`WS_TEXT`）中引入条件分流路由：
     
     - `if (device == "servo1")` $\rightarrow$ 执行本地引脚 `servoLight.write(value);`
     
     - `if (device == "lego")` $\rightarrow$ 转换成乐高标准的 8 字节蓝牙包，调用蓝牙特征值发送函数。
     
     - `if (device == "mouldking")` $\rightarrow$ 转换成宇星模王标准的 4 字节蓝牙包发送。

### 任务 4.2：移动节点失控守护、自动重连与时序调优

- **需求描述：** 针对火车在轨道上奔跑、远离固定网关导致的丢包、断连风险，以及 ESP32 单天线 Wi-Fi/蓝牙时分复用冲突问题进行工业级优化。

- **验收标准：** 用手机、iPad 同时打开网页，频繁交替控制物理舵机与无线积木马达，小火车在10-15米范围内匀速行驶，系统连续稳定运行 15 分钟不崩溃、不失控。

- **具体执行步骤：**
  
  1. **编写双路积木蓝牙心跳守护进程：** 在 `loop()` 中利用 `millis()` 建立无阻塞软件定时器。对于宇星模王等缺乏原生防失控固件的设备，每 400ms 强制发送一次当前速度指令维持链路；一旦彻底断连，网关立即停止发送，火车安全刹车。
  
  2. **非阻塞自动重连机制：** 继承 `BLEClientCallbacks` 接口，重写 `onDisconnect()` 函数。当小火车跑远或受人体阻挡异常断连时，立即将全局状态标志位置为 `false`，并自动触发异步重新扫描。**严禁使用阻塞式死循环死等重连**，确保重连期间 Wi-Fi 网页端依然可控且能实时显示 `🔴 积木已断开`。
  
  3. **定时内存大扫除：** 在 `loop()` 主循环中，每 2 秒强制调用一次 `ws.cleanupClients()`，及时剔除因手机锁屏、断网而残留的死掉的 TCP 网页句柄，杜绝运行内存（SRAM）碎片化导致的频繁无故重启。
  
  4. **成品脱机运行：** 项目验收通过后，拔掉电脑 USB 线，将 ESP32 直接插在标准手机充电头或充电宝上，放置在火车轨道几何中心处，实现完全脱离电脑的独立硬件摆玩。
